## 1. Сплит: одна операция — несколько категорий

- В карточке операции кнопка **«Разделить по категориям»**.
- Строки «категория + сумма»: «+ категория» добавляет, «×» удаляет (минимум две),
  «убрать разбивку» возвращает обычный режим.
- Подсказка снизу: «Осталось: X ₽» / «Перебор: X ₽» / «Распределено полностью».
- Сохранить нельзя, пока сумма частей не равна сумме операции.
- В списке — «Продукты +1», в подписи перечислены все категории.

В данных: `splits: [{categoryId, amount}]`, сумма частей = `amount`, `categoryId` = первая часть.
Баланс и прогноз считаются по `amount` — разбивка на них не влияет, синхронизация не меняется.

## 2. Фото чеков: Яндекс.Диск + локальный кэш

- В форме операции — «Добавить фото» (на телефоне открывает камеру) и превью.
  Тап по превью — просмотр на весь экран.
- Фото сжимается в браузере: длинная сторона до 1600 px, JPEG 0.82 (≈150–400 КБ вместо 3–8 МБ).
- Копия сразу кладётся в **IndexedDB** — открывается мгновенно и без сети.
- Файл уходит на Диск в `app:/Cash/photos/<имя>.jpg`. Если сети нет — фото остаётся
  помеченным «в очереди» и догружается при следующей синхронизации.
- В операции хранится только имя файла (`photo`), JSON не раздувается.
- «Убрать фото» удаляет и локальную копию, и файл на Диске.
- В списке операций с чеком есть отметка «фото».

## Как поставить

1. GitHub → **Add file → Upload files** → загрузить 5 файлов в корень → коммит в `main`.
2. Pages пересоберётся за минуту.
3. Чтобы устройство не взяло старый кэш: F12 → Application → Service Workers → **Unregister**,
   затем Ctrl+F5. Версия кэша поднята до `cash-v5`.

## Как проверено

Chromium (Playwright), мок API Яндекса.

**Сплит — 18 проверок, все зелёные:** открытие формы, блок разбивки, 1000 = 600 + 400,
«+1» в списке, восстановление строк при правке, отказ при неверной сумме (700 ≠ 1000),
«убрать разбивку», доход со сплитом, баланс по полной сумме.

**Фото — 21 проверка, все зелёные:** поле в форме, сжатие 2000×1500 → 1600×1200,
имя файла в операции, пут�� `app%3A%2FCash%2Fphotos%2F…` в API, PUT с `image/jpeg` и телом
19 КБ, копия в IndexedDB, отметка «фото» в списке, превью после перезагрузки,
полноэкранный просмотр, удаление из операции + из кэша + DELETE на Диске,
догрузка офлайн-фото через `flushPendingPhotos`.
